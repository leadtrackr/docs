The Channel Flow Tracker records which marketing channels brought a visitor to your site, long before they fill in a form. When a lead comes in, that journey is attached to it, so you can see that the "direct" conversion actually started with a Google Ads click three weeks earlier.

## Two Ways to Set This Up

Channel Flow runs either as a tag in Google Tag Manager or straight from the LeadTrackr WordPress plugin. Both routes write the same two cookies in the same format and follow the same logic, so the attribution you end up with is identical. Pick one:

- **Your site already uses GTM** — use the tag. It also covers pages that are not WordPress (a campaign landing page on another platform, a booking subdomain), and it is the only route with a configurable session timeout.
- **There is no GTM on the site** — use the plugin. One switch in wp-admin, no container to publish and no second tool to keep in sync.

## Set Up with Google Tag Manager

### Step 1: Add the LeadTrackr Tag to Your GTM Container

1. Go to your **container** in Tag Manager
2. Click **Templates** → **Search Gallery**
3. Look for **LeadTrackr tag**
4. Click **Add to Workspace**

<Frame>
  <img src="/images/lead-sources/gtm-1.png" alt="Search GTM gallery" />
</Frame>

### Step 2: Create a New LeadTrackr Tag

1. Go to **Tags** and click **New**
2. Select **LeadTrackr Tag** as the tag type
3. Choose **Channel Flow Tracker** as the tag type

<Frame>
  <img src="/images/lead-sources/channel-flow-1.png" alt="Channel Flow Tracker tag type" />
</Frame>

#### Optional settings

| Setting | Default | What it does |
| --- | --- | --- |
| **Session Timeout (minutes)** | 30 | How long a visitor can go without a pageview before their next visit counts as a new session. Matches the GA4 default. |
| **Use Custom UTM Parameters** | off | Use your own parameter names instead of `utm_source`, `utm_medium` and the rest. |
| **Enable debug mode** | off | Logs the resolved channel and session state to the browser console in GTM preview mode. |

### Step 3: Add a Trigger

Attach an **All Pages** trigger to the LeadTrackr tag. This ensures the Channel Flow Tracker can capture UTM parameters and build the full user journey before a lead is submitted.

<Warning>
If you're using **Google Consent Mode**, keep the following in mind:

- If your LeadTrackr tag is restricted to fire **only when analytics_storage is granted**, make sure the tag fires **after consent has been given**
- This allows LeadTrackr to correctly store pageview data and attribution before the lead event occurs
- If the tag fires before consent is granted, the channel flow may be incomplete or missing
</Warning>

<Frame>
  <img src="/images/lead-sources/channel-flow-2.png" alt="All Pages trigger" />
</Frame>

### Step 4: Publish Your Container

Once your tag and trigger are configured, **publish your GTM container**.

Your channel flow tracking is now active and will be included automatically in new lead entries.

## Set Up with the WordPress Plugin

The LeadTrackr plugin ships Channel Flow itself. It does not need the GTM tag, and it does not load anything from a CDN — the script is served as a first-party file from your own site, so there is no extra domain to allow in a consent banner or a content security policy.

### Step 1: Install and Connect the Plugin

Channel Flow lives inside the plugin you already use for your forms, so there is nothing extra to install. If LeadTrackr is not on the site yet, work through [Connect WordPress Forms as a Lead Source](/lead-sources/wordpress-forms) first: the plugin has to be activated and connected to your project ID before Channel Flow has anywhere to send its data.

### Step 2: Switch Channel Flow On

1. In your WordPress dashboard, go to **LeadTrackr** → **General**
2. Open the **Channel Flow** section
3. Turn on **Enable Channel Flow tracking**
4. Click **Save**

That is the whole setup. From the next pageview onward, the plugin builds the channel path and attaches it to every form submission it sends to LeadTrackr.

<Warning>
**New installs have Channel Flow on, sites that upgraded do not.** A plugin update never changes how an existing site behaves, so if LeadTrackr was already running before this version, the switch starts off and you have to turn it on deliberately. Check the setting after updating — otherwise leads keep arriving without a channel path, and nothing on the site tells you why.
</Warning>

### Step 3: Custom UTM Parameter Names (Optional)

If your campaigns use parameter names of your own instead of the standard UTMs, open **Use custom UTM parameter names** and fill in the five fields, one per parameter. Leave the section alone if you use `utm_source` and friends — that is what every ad platform generates by default.

<Info>
The WordPress route has no session timeout setting. It uses the 30-minute default, the same value GA4 uses and the same default the GTM tag ships with. If you need a different window, use the GTM route.
</Info>

## Enable UTM Tracking in Your Ad Platforms

Whichever route you set up, the quality of your channel flow depends on what your ads put in the URL. To get accurate source/medium/channel data in LeadTrackr, make sure **UTM parameters** are added to your ads.

Channel Flow saves the following parameters:

- `utm_source`
- `utm_medium`
- `utm_campaign`
- `utm_content`
- `utm_term`

<Tip>
No UTM parameters on your Google Ads campaigns? Channel Flow falls back to the click ID that auto-tagging adds to the URL (`gclid`, `gbraid` or `wbraid`), and records the visit as `google / cpc`. Microsoft Ads works the same way through `msclkid`. UTM parameters still give you far more detail, since the fallback cannot tell you which campaign the click came from.
</Tip>

## How ChannelFlow Records Sessions

Every entry in a channel path represents **one session**, not one pageview. Browsing five pages in a row produces a single entry, so the path stays readable no matter how much someone clicks around.

A new session starts when either of these happens:

- **The visitor has been inactive.** No pageview for longer than the session timeout, 30 minutes by default. Coming back the next day therefore starts a new session, even if they arrive through the same channel as before.
- **A new campaign brings them in.** UTM parameters or an ad click ID that resolve to a different channel than the last entry. Reloading the same landing page does not add an entry, because the channel has not changed.

A journey then reads like this:

| # | Channel | When | Landing page |
| --- | --- | --- | --- |
| 1 | google / cpc | 21 July, 08:33 | /conversion-tracking |
| 2 | direct / none | 26 July, 19:02 | /pricing |
| 3 | nieuwsbrief / email | 5 August, 09:15 | /demo |

### How the channel is determined

The first rule that matches wins:

| Rule | Result |
| --- | --- |
| UTM parameters in the URL | The UTM values themselves |
| `gclid`, `gbraid` or `wbraid` in the URL | `google / cpc` |
| `msclkid` in the URL | `bing / cpc` |
| The visitor came from a search engine | For example `google / organic` |
| The visitor came from another website | For example `www.example.com / referral` |
| Anything else | `direct / none` |

<Info>
Two details worth knowing when a result surprises you.

An ad click ID only counts when it is in the URL of that visit and the visitor did not arrive from your own site. Google Consent Mode can append the click ID to internal links when a visitor declines consent, and those are carried over rather than new clicks.

A visitor who returns after the session timeout through a link on your own site is recorded as `direct / none`, because there is no external source to attribute the visit to. Google Analytics 4 treats this the same way.
</Info>

## Cookies Used by ChannelFlow

ChannelFlow uses two first-party cookies to build and maintain the visitor's channel journey.

### lt_channelflow

The `lt_channelflow` cookie stores the visitor's marketing channel path. It contains attribution data such as the source, medium, campaign and landing page for each recorded session. The cookie does not contain personal information or a unique visitor identifier and is used solely for first-party analytical attribution.

### lt_session

The `lt_session` cookie is a lightweight session cookie used to determine whether a visitor is still within the same browsing session. By default, it expires after 30 minutes of inactivity. It does not store any visitor information and simply indicates whether a new ChannelFlow session should be started.

Together, these cookies allow ChannelFlow to accurately reconstruct a visitor's marketing journey without relying on persistent user identifiers or cross-site tracking.

## Privacy by Design

ChannelFlow was designed according to privacy-by-design principles. Instead of generating or storing a unique visitor identifier, it stores only the visitor's marketing channel path in a first-party cookie. In other words, ChannelFlow stores the marketing journey, not the identity of the visitor.

The cookie itself does not contain personal information or a unique identifier. It stores only attribution data, such as the marketing source, medium, campaign and landing page of each session. It is not used for advertising, profiling, remarketing or cross-site tracking.

The cookie is only read when a visitor submits a form or otherwise becomes a converted lead. At that point, the stored channel path is attached to the lead in LeadTrackr for first-party attribution reporting.

When determining how to classify the ChannelFlow cookie, you may want to consider the following:

- No unique visitor identifier is generated or stored.
- The cookie is first-party and remains on your own domain.
- It stores only marketing attribution data for analytical purposes.
- It is not used for advertising, profiling or cross-site tracking.
- The cookie is only read when a lead is created and the attribution data is attached to that lead.

<Note>
Whether the ChannelFlow cookie should be classified as a functional or analytical cookie depends on your own legal assessment, local regulations and the way it is implemented within your organisation.
</Note>
